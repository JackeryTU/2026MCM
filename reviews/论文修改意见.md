## 使用规则

1. 每轮审查前先提交并推送当前论文，填写基准 commit，避免页码和行号失效。
2. `必改`、跨文件问题和有争议的问题必须登记；简单措辞问题可以只用 GitHub 行内评论或线下沟通。
3. 位置优先写文件名、章节、公式号、图表号或稳定标签；页码只能作为辅助定位。
4. 完成修改后填写实际 commit，不删除原意见。
5. 不采纳的意见标记为 `已确认不改`，并记录讨论后的理由。
6. 新一轮审查开始时，将上一轮移动到下方“历史轮次”，再清空当前台账。

## 模型或结果更新通知模板

论文开始撰写后，如果建模手调整模型、参数、代码、结果或图片，不直接根据自己电脑中的旧论文改写 `paper/`，而是在本台账新增一条 `必改` 记录，交给论文手同步正式论文：

```markdown
## R-XXX 模型或结果更新

- 优先级：[必改]
- 影响位置：论文中的章节、公式、表格或图片
- 变更原因：为什么需要调整
- 模型变化：旧模型与新模型的关键差异
- 结果变化：受影响的主要数值或结论
- 权威代码：问题X_求解.py 或 .m
- 权威结果：results/中的具体文件
- 权威图片：figures/中的具体文件
- 提出人：建模手姓名
- 负责人：论文手姓名
- 状态：待处理
```

论文手更新 `paper/` 并完成编译后，将状态改为 `已处理待复核`；建模手或审查人确认公式、参数、数值、图片和结论均与新版模型一致后，改为 `已关闭`。
