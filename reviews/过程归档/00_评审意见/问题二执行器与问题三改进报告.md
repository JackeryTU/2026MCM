# 问题二执行器与问题三改进报告

## 1. 报告范围

本报告说明问题二的贪心与 MPC 如何统一评价口径，以及问题三针对合同调整时序和风险余量传递所做的修复。所有年度成本均由当前代码重新运行得到，统计窗口为 2025-02-01 至 2025-12-31，共 334 天；2025 年 1 月只用于连续预运行和传递储能 SOC，不计入年度成本。

最终主参数为：Q2 使用预测器 F1、历史窗口 `W=35`、分位水平 `alpha=0.805`、MPC 时域 `H=49`；Q3/Q4 使用 F1、`W=35`、`alpha=0.7725`、`H=6`。旧 `W=30, alpha=0.9, H=36` 仅作为原始基准。储能初始电量为 6000 kWh，容量、效率、功率约束及结算价格均保持原模型不变。

## 2. 统一评价口径

### 2.1 信息边界

贪心和 MPC 在第 `t` 槽决定动作时，都只能读取当前时刻已获准的预测和此前已经完成时段的信息，不读取第 `t` 槽尚未实现的实际负荷和实际光伏。

统一执行顺序为：

1. 根据当前可用的风险修正预测决定计划充、放电动作；
2. 动作确定后，才读入当前槽实际负荷和实际光伏；
3. 实际值只用于可行性裁剪、母线平衡、应急购电和现金结算；
4. 裁剪只能缩减已经决定的充、放电动作，不能根据当前实际缺口临时增加放电；
5. 当前槽实际末态传递给下一槽，并连续传递到下一日。

因此，修改后的贪心是“预测驱动贪心”，不是原先使用当前槽实测盈缺的“即时反馈贪心”。

### 2.2 两种执行器的唯一差别

在统一口径下，两种执行器共享同一合同、预测方法、风险余量、实际路径、储能约束、裁剪器和结算规则。

- 预测驱动贪心：只根据当前一个槽的风险修正预测盈缺决定充放电；
- MPC：根据从当前槽开始的未来 36 槽风险修正预测联合优化，但只执行第一槽动作。

这使二者的差异集中在是否利用跨时段价格和储能状态信息，而不是谁提前读取了当前实际值。

## 3. 问题二的具体改动

### 3.1 将问题二正式执行器改为 MPC

修改位置：`solution_lib.py::run_year_q2`，当前约第 118--140 行。

原流程为：

```text
安全轨迹 -> 日前合同 LP -> 当前槽实测反馈贪心 -> 结算
```

修改后流程为：

```text
安全轨迹 -> 日前合同 LP -> Q2 H=49 / Q3-Q4 H=6 滚动 MPC -> 事后裁剪 -> 结算
```

`run_year_q2` 默认参数新增 `executor="mpc"`，并调用问题三、四共用的 `run_year_q34`。问题二配置固定为：

```python
mode="uniform"
Q2 H=49；Q3/Q4 H=6
allowed=(0,)
updates=()
pv_source="center"
executor="mpc"
```

这表示问题二没有日内合同调整，只使用 F1 中心预测及其逐槽残差分位修正。

### 3.2 增加同口径预测驱动贪心

修改位置：`solution_lib.py::rolling_execute_q34`，当前约第 534--596 行。

执行器新增 `executor` 参数，允许取 `mpc` 或 `greedy`。预测驱动贪心首先计算：

```text
预测盈余 = max(合同电量 + 风险修正光伏预测 - 风险修正负荷预测, 0)
预测缺口 = max(风险修正负荷预测 - 合同电量 - 风险修正光伏预测, 0)
```

再按照电池功率和 SOC 约束决定当前槽充、放电量。实际负荷和光伏不参与动作决策，只在随后调用 `microgrid_core.py::clip_slot` 时进入。

### 3.3 增加入口参数

修改位置：`问题2_求解.py`，当前约第 164--176 行。

新增参数：

```text
--main-only             只运行主配置
--executor mpc          使用统一口径 MPC
--executor greedy       使用统一口径预测驱动贪心
```

问题二正式结果使用 `mpc`；`greedy` 只作为执行器对照。

## 4. 问题三的具体改动

### 4.1 修复合同调整的时间顺序

修改位置：`solution_lib.py::run_year_q34` 中的 `update_contract`，当前约第 689--708 行。

原代码在每天开始时一次性计算 6:00、12:00、18:00 三次合同调整，三次均错误使用日初 SOC。这导致调整 LP 看不到上午或中午已经发生的实际充放电状态。

修改后，合同调整嵌入逐槽执行循环：

- 到达 6:00 时，使用 6:00 的实际 SOC 重算 6:00 之后的合同；
- 到达 12:00 时，使用 12:00 的实际 SOC 重算 12:00 之后的合同；
- 到达 18:00 时，使用 18:00 的实际 SOC 重算 18:00 之后的合同。

每次调整只改变当前时刻之后的合同，已经执行的合同保持不变。

### 4.2 统一合同调整目标与最终结算基准

问题三最终结算始终比较 0:00 原计划 `p` 与最终合同 `q`。原代码连续调整时却以最近一次 `q` 为新的优化基准，调整目标与最终结算公式不完全一致。

修改后，每次合同重算均以原计划 `p[t:]` 为基准：

```python
mc.contract_update_lp(p[t:], ..., current_s, ...)
```

从而保证优化时采用的上调、下调费用与最终 `settle_q3(p, q, ...)` 的结算口径一致。

### 4.3 把风险余量传入 MPC 执行层

修改位置：`solution_lib.py::run_year_q34`，当前约第 674--708 行。

原代码只在日前合同和合同调整阶段使用分位风险余量，滚动 MPC 执行阶段重新退回中心预测。这会使合同层购买的尾部保障无法约束储能的跨时段分配。

修改后，对每个获准光伏预报版本分别构造：

```python
safe_load_curves[r], safe_pv_curves[r] = safe_from_reserve(...)
```

并把同一组风险修正轨迹同时传给：

- 0:00 日前合同 LP；
- 6:00、12:00、18:00 合同调整 LP；
- 每 10 min 重算的滚动 MPC。

因此风险余量不再只决定“买多少合同电”，还会影响 MPC 如何保留和使用储能。

### 4.4 修复问题三覆盖率计算

修改位置：`问题3_求解.py::_coverage`，当前约第 85--93 行。

原覆盖率计算虽然构造了官方光伏预报版本，却仍使用 F1 光伏中心预测 `vhat` 评价安全轨迹，与实际进入问题三合同和 MPC 的预测源不一致。

修改后使用对应获准版本 `pv_ver[d]`：

```python
R[i] = actual_net_load - (lhat - pv_ver[d] + reserve)
```

新主配置下 Q3 安全轨迹覆盖率约为 76.95%；该值按 alpha=0.7725 和新的 W=35 风险参数重算。

## 5. 重新运行结果

| 方案 | 总成本/元 | 应急购电/kWh | 说明 |
|---|---:|---:|---|
| 问题二原实测反馈贪心 | 14,485,387.74 | 46,745.89 | 修改前结果；提前使用当前槽实测，不再作为公平对照 |
| 问题二统一预测驱动贪心 | 14,875,117.17 | 147,559.99 | 当前槽只用风险修正预测 |
| 问题二优化后 MPC | 14,786,101.35 | 245,483.29 | 正式主方案，F1-W35-alpha0.805-H49 |
| 问题三修改前 MPC | 16,337,994.80 | 397,847.66 | 合同调整时序错误，执行层未继承风险余量 |
| 问题三优化后 MPC | 14,664,345.40 | 210,761.48 | 正式主方案，F1-W35-alpha0.7725-H6 |
| 问题三冻结合同基线 | 16,315,304.85 | 416,687.51 | 仍接收 6/12/18 新预报，但禁止调整合同 |

旧配置下问题二统一预测驱动贪心比统一 MPC 少支出 42,384.32 元；该结果仅作为原始基准，不用于新主配置结论。不能据此恢复原实测反馈贪心，因为后者使用了更多信息。

问题三修复后比修改前少支出 1,369,497.96 元，降幅约 8.38%；应急购电由 397,847.66 kWh 降至 87,488.76 kWh，说明主要问题确实位于合同调整时序和风险余量未进入执行层。

问题三修复后比严格冻结合同基线少支出 1,346,808.01 元，降幅约 8.25%。该差值在预测、MPC、风险参数和信息到达时刻均相同的条件下得到，可以解释为合同调整权带来的系统收益。

问题三修复后仍比问题二统一 MPC 高 50,995.36 元，约 0.342%。这不是问题三改进无效：两问的 0:00 光伏预测源、风险校准方式和合同调整结算规则不同，问题三并不是问题二方案的严格可行域扩张。问题三价值应优先通过其自身冻结合同基线评价。

## 6. 结论与使用口径

1. 原问题二实测反馈贪心存在信息优势，原总成本不能与无当前槽实测的 MPC 公平比较。
2. 新主配置下，问题二 MPC 总成本为 14,786,101.35 元，问题三 MPC 总成本为 14,664,345.40 元；旧参数结果保留为历史基准，贪心仍仅作同信息集对照。
3. 问题三原高成本主要不是“MPC 天生较差”，而是合同调整时序错误、调整目标与结算基准不一致，以及风险余量没有进入 MPC 执行层共同造成的。
4. 参数优化后的问题三总成本为 14,664,345.40 元；Q4 联动重算后，Q4-2 median30 为 17,378,687.69 元，Q4-3 median30 为 15,465,962.60 元。
5. 报告或论文中不得再把 14,485,387.74 元称为统一口径问题二结果，也不得继续使用 16,337,994.80 元作为修复后问题三结果。
