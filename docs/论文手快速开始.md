# 论文手快速开始

这份说明写给第一次使用 Git 和 GitHub 的论文手。你不需要理解 Git，也不需要输入命令，按顺序安装软件并双击脚本即可。

当前团队已经建好私有 GitHub 仓库，也已经邀请你加入。正式论文只在项目的 `paper/` 文件夹中维护。

## 一、你的职责与硬性约束

### 你负责什么

- 在 `paper/` 中撰写、修改和编译正式 LaTeX 论文。
- 根据 `题目分析报告.md`、`术语表格.md`、`results/` 和 `figures/` 准确描述模型与结果。
- 处理 `reviews/论文修改意见.md` 中分配给论文手的意见。
- 检查公式、符号、单位、数值、图表、引用、匿名要求和排版。
- 定稿时从 `paper/` 重新编译 PDF，再由团队确认后放入 `submission/`。

### 你不能做什么

- 不擅自修改模型、求解代码、`results/` 中的权威数值或根目录 `figures/` 中的权威图片。
- 不根据猜测补造公式、参数、数值、实验结果或参考文献。证据不足时，通知建模手／编程手补充。
- 不从旧论文、旧 PDF 或聊天截图抄取结果；数值以最新的 `results/` 为准，候选图以最新的 `figures/` 为准。
- 不直接编辑 PDF；必须修改 LaTeX 源码并重新编译。
- 不用 `参考初稿-LaTeX/` 覆盖 `paper/`，不把 `参考初稿.pdf` 当作参赛论文。
- 未经团队确认，不直接修改或删除 `data/`、代码、结果和其他成员负责的文件。

### 每次交付前必须做到

1. 开始前在群里说明准备修改的论文文件或范围，避免两个人同时修改同一文件。
2. 开始工作前运行 04，完成一小段后运行 03，不长期只保存在自己的电脑上。
3. 实际编译 LaTeX；“源码看起来没问题”不等于论文完成。
4. 确认论文中的数值、参数、图片和结论与最新建模结果一致。
5. 检查上传脚本列出的文件；出现不属于论文工作的文件时取消上传并询问负责人。
6. 处理修改意见后，将状态改为“已处理待复核”，不能由论文手自己直接改为“已关闭”。

## 二、第一次使用：只做一次

### 第 1 步：接受仓库邀请

1. 登录队长邀请的那个 GitHub 账号。
2. 打开 GitHub 发来的邀请邮件或通知，点击接受邀请。
3. 确认登录后能看到团队私有仓库：<https://github.com/JackeryTU/2026MCM>。

如果仓库页面显示 404 或无权访问，先找队长确认邀请的账号，不要继续操作。

### 第 2 步：安装 Git

1. 打开 <https://git-scm.com/download/win>。
2. 下载并运行 Git for Windows 安装程序。
3. 保持默认选项，一直点击 Next，最后点击 Install。
4. 安装完成后关闭安装程序。

如果此前打开过脚本窗口，请先关闭，再重新双击脚本，让电脑识别刚安装的 Git。

### 第 3 步：准备空文件夹

1. 在方便找到的位置新建一个空文件夹，例如 `D:\数学建模比赛`。
2. 向队长索要 `02_队员首次下载项目.cmd`。
3. 只把这个脚本放入刚才的空文件夹。

不要从 GitHub 网页下载 ZIP。后续协作必须使用脚本下载的项目文件夹。

### 第 4 步：第一次下载项目

1. 双击 `02_队员首次下载项目.cmd`。
2. 看到确认提示后输入 Y，按回车。
3. 如果浏览器弹出登录页面，登录已经接受邀请的 GitHub 账号并授权。
4. 按提示输入自己的 GitHub 用户名和邮箱。
5. 等待窗口显示“[完成]”。

脚本旁边会出现新的 `2026MCM` 文件夹。以后只在这个文件夹里工作，不再运行 02。

### 第 5 步：确认下载成功

打开 2026MCM，应该至少能看到：

    paper/
    reviews/
    results/
    figures/
    03_上传我的修改.cmd
    04_获取队友最新文件.cmd

看到这些内容，就可以开始协作。

## 三、以后每次写论文

固定顺序：

    获取队友最新文件 → 修改并编译正式论文 → 上传我的修改

具体操作：

1. 打开自己电脑中的 2026MCM 文件夹。
2. 在群里说明准备修改的论文文件或内容。
3. 双击 `04_获取队友最新文件.cmd`。
4. 看到“[完成]”后，查看 `reviews/论文修改意见.md`。
5. 在 `paper/` 中修改 LaTeX 正式论文。
6. 编译论文，检查公式、表格、图片、引用和版面。
7. 双击 `03_上传我的修改.cmd`。
8. 检查窗口列出的文件。确认都是自己本次要改的文件后，输入 Y。
9. 输入修改说明，例如：`paper: 完成问题一模型描述`。
10. 看到“[完成]”后，在群里说明已经上传。

建议每完成一节或一项明确修改就上传一次。

## 四、收到模型或结果更新

1. 双击 `04_获取队友最新文件.cmd`。
2. 打开 `reviews/论文修改意见.md`，找到对应意见。
3. 从 `results/` 和 `figures/` 获取最新结果，不要从旧 PDF 抄数值。
4. 修改 `paper/` 中受影响的公式、参数、表格、图片和结论。
5. 编译并检查论文。
6. 把意见状态改为“已处理待复核”。
7. 双击 `03_上传我的修改.cmd` 完成上传。
8. 通知建模手复核。

`参考初稿-LaTeX/` 和 `参考初稿.pdf` 只是 Skill 提供的参考材料，不能覆盖 paper，也不能作为参赛论文提交。

## 五、脚本提示失败怎么办

### 获取时提示本机还有修改

先运行 03 保存修改，再运行 04 获取更新。

### 上传时提示队友已经先上传更新

你的修改已经安全保存在电脑中。运行 04，成功后再运行 03。

### 出现 conflict、rebase failed 或看不懂的报错

立即停止，不要继续尝试命令。保留窗口，把完整截图发给队长。

不要自行使用 force push、reset --hard、git clean 或 checkout 撤销文件。

## 六、最后速查

    第一次：安装 Git → 接受邀请 → 运行 02
    每天开始：运行 04
    写作位置：paper/
    完成一小段：编译检查 → 运行 03
    模型有更新：运行 04 → 看 reviews → 改 paper → 运行 03
    出现冲突：停止并找队长

更完整的规则见 [论文手 Git 协作说明](论文手Git协作说明.md)。
