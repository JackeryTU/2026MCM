# 论文手 GitHub 协作说明

## 只需记住

```text
第一次加入项目：02_队员首次下载项目.cmd
每次开始写论文：04_获取队友最新文件.cmd
每次完成一小段：03_上传我的修改.cmd
```

正式论文只在 `paper/` 中维护。`参考初稿-LaTeX/` 和 `参考初稿.pdf` 只是参考资料，不能直接作为参赛论文。

## 第一次加入项目

1. 安装 Git for Windows：<https://git-scm.com/download/win>。
2. 登录自己的 GitHub 账号，并接受队长发来的私有仓库邀请。
3. 在电脑上新建一个空文件夹，例如 `D:\MathModel`。
4. 把队长发来的 `02_队员首次下载项目.cmd` 放进这个空文件夹。
5. 双击脚本，根据中文提示输入 `Y`。
6. 如果浏览器弹出登录页面，登录收到邀请的 GitHub 账号。
7. 输入自己的 GitHub 用户名和邮箱。
8. 出现“[完成]”后，进入新生成的 `2026MCM` 文件夹工作。

以后不需要再运行“02_队员首次下载项目”。

## 每次写论文的标准流程

1. 在群里说明准备修改的论文文件或内容。
2. 双击 `04_获取队友最新文件.cmd`。
3. 查看 `reviews/论文修改意见.md`，确认是否有模型或结果更新。
4. 在 `paper/` 中写正式论文。
5. 实际编译论文，检查公式、图表、引用和版面。
6. 双击 `03_上传我的修改.cmd`。
7. 检查脚本列出的文件，确认无误后输入 `Y`。
8. 输入提交说明，例如 `paper: 完成问题一模型描述`。
9. 出现“[完成]”后，在群里说明已经上传。

建议每完成一节或一项明确修改就上传，不要长时间只保存在自己的电脑上。

## 收到模型或结果更新时

建模手会在 `reviews/论文修改意见.md` 中登记影响。论文手按以下顺序处理：

1. 运行 `04_获取队友最新文件.cmd`。
2. 阅读对应意见，找到新版代码、结果和图片。
3. 根据权威文件修改 `paper/` 中的公式、参数、表格、图片和结论。
4. 编译并检查正式论文。
5. 把意见状态改为 `已处理待复核`。
6. 运行 `03_上传我的修改.cmd`。
7. 通知建模手或审查人复核。

建模结果的权威来源是 `results/` 和 `figures/`，不要从旧 PDF 手工抄数值。

## 论文审查流程

```text
论文手上传 paper
→ 审查人运行“04_获取队友最新文件”
→ 审查意见写入 reviews/论文修改意见.md
→ 审查人运行“03_上传我的修改”
→ 论文手运行“04_获取队友最新文件”
→ 修改 paper 并编译
→ 状态改为“已处理待复核”
→ 复核通过后改为“已关闭”
```

正式论文是否拆分章节由论文手决定，不作强制要求。

## 常见问题

### “04_获取队友最新文件”会覆盖我正在写的论文吗？

不会。只要本地还有未提交修改，获取脚本就会停止。先运行“03_上传我的修改”保存修改，再运行“04_获取队友最新文件”。

### 上传时发现 GitHub 已更新怎么办？

你的论文修改已经保存在本地。按以下顺序处理：

```text
获取并整合队友更新
→ 上传自己的论文版本
```

### 建模手电脑上的旧论文会覆盖我的新论文吗？

只要建模手没有修改 `paper/`，就不会。Git 只上传实际发生变化的文件，不会把整个旧文件夹覆盖到 GitHub。

### Skill 又生成了一份参考初稿怎么办？

只把它当参考。不得用 `参考初稿-LaTeX/` 覆盖 `paper/`，也不得把 `参考初稿.pdf` 当作参赛 PDF。

### 不小心保存了建模手负责的文件怎么办？

运行“03_上传我的修改”查看文件列表，但不要输入 `Y`。把文件名发给建模手和队长，由他们判断是否保留。

### 两个人同时修改论文怎么办？

同一时刻尽量只让一个人修改同一个论文文件。如果出现 `conflict` 或 `rebase failed`，立即停止，把完整窗口截图发给队长共同处理。

### PDF 可以直接修改吗？

不直接修改最终 PDF。应修改 `paper/` 中的 LaTeX 源码，重新编译，再更新 `submission/`。

### “03_上传我的修改”中的 M、??、D 是什么意思？

- `M`：文件被修改；
- `??`：新增文件；
- `D`：文件被删除。

看到意外的 `D` 或不属于论文工作的文件时，取消上传并联系队长。

## 必须停止并找队长的情况

- 出现 `conflict` 或 `rebase failed`；
- 不确定某个文件是否应该上传；
- 误改了建模、代码或结果文件；
- 克隆失败或没有私有仓库权限；
- 脚本显示的仓库地址不对；
- 出现其他看不懂的失败信息。

不要自行运行 `git push --force`、`git reset --hard`、`git clean` 或 `git checkout -- 文件名`。

## 最后速查

```text
第一次：02_队员首次下载项目
开始写论文：04_获取队友最新文件
完成一小段：编译检查后运行“03_上传我的修改”
收到模型更新：获取最新文件 → 看 reviews → 改 paper → 上传修改
上传时发现远程更新：获取最新文件 → 上传修改
发生冲突：停止并找队长
```
